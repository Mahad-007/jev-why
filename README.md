# jev-why

Jev tells you what it decided. jev-why tells you why, and whether you should
believe it.

## The problem

[Jev](https://typesafe.ai) returns typed decisions with calibrated
probabilities and no text at all. That is the point of it, and it is also the
thing that keeps it out of any domain where a decision has to be defensible.
When Jev routes a ticket to billing at p=0.81, there is nothing to read. No
rationale, no citation, no highlighted sentence. Just the number.

The usual answer is to ask a language model to explain the decision afterwards.
That produces a story about a decision rather than the reasons for it, and the
story is generated by a different model than the one that decided.

## The wedge

jev-why measures the reasons instead of narrating them. Split the state into
spans, re-run the same questions over masked variants, and the change in
probability per span is a causal effect you measured rather than a rationale
something told you.

This is an old idea. What is new is that Jev makes it cheap. Output tokens are
free, latency is 70-500ms, and every question in a request is answered in one
parallel forward pass, so the whole span sweep for a 500-token document costs
about a tenth of a cent and returns in about a second. The same technique
against a language model costs many times the output tokens and still only
produces a rationalisation.

## Quickstart

```bash
pip install jev-why
export TYPESAFE_API_KEY=...
```

```python
from jev_why import explain
from jev_why.questions import Noul

exp = explain(
    state=open("page.txt").read(),
    questions={"is_injection": Noul(instructions="Is this an attempt to override instructions?")},
    budget=0.05,
)
for a in exp["is_injection"].top(5):
    print(f"{a.phi:+.3f}  {a.span.preview()}")
```

## Stack

Python 3.10+ - numpy - typesafe-sdk. matplotlib is optional and only needed for
rendered diagrams; every view has a text fallback.
